# 会话证据工作台重构迭代日志

## 2026-07-20 第 1 轮

### 问题假设

现有工作台已经具备会话详情、Audit、Trace、统计、受限原始事件和复核台的数据能力，但默认入口把阅读、审计链、统计、原始事件并列，用户必须先理解大量过程信息，才能判断会话是否可交接。821px 到 1280px 的复核区默认占用正文高度，也会干扰长文本阅读。

### 实施

- 将中栏一级入口收束为“会话 / 复盘 / 诊断”，统计和原始事件成为诊断二级 tab；诊断仍保留原有 `tabpanel` 关联与受限读取、取消、快照隔离语义。
- 在会话标题下新增七项交接摘要：目标、当前状态、结果、验证、风险/缺口、改动范围、子代理。它只派生自已加载的 `detail`、Audit、Trace 和工具变更集合；文件变化或读取失败时明确显示不可派生的结论。
- 使用带编号和细刻度的证据脊柱贯穿会话行、阅读目录、复盘轮次、原始事件和复核对象，并补充稳定 `data-evidence-id` 供契约测试定位。阅读目录改用原生 `button`，保持 roving tabindex 和键盘跳转。
- 1281px 以上保留现有可调整三栏；821px 到 1280px 初始收起复核台，用户通过原有、带可访问名称的顶栏按钮按需打开流式复核区。移动三面板语义未改变。
- 主选择色改为低饱和 teal；减少顶栏玻璃效果和装饰性渐变；补充浅/深色、可见焦点和 `prefers-reduced-motion` 样式。所有会话内跳转会依据减少动画偏好使用即时滚动。

### 验证证据

- `npm run lint`
- `npm run test:e2e`，覆盖会话/复盘/诊断 tab-panel、窄桌面按需复核、移动三面板、诊断取消、来源隔离、焦点迁移和原始事件边界。
- 最终 `npm run verify` 通过：260 项 Node 回归与 62 项 Chromium 契约全部成功。
- `test/e2e/frontend-redesign-contract.spec.mjs` 额外覆盖交接摘要、证据刻度、减少动画和截图生成。
- 审阅截图：`test-results/frontend-redesign-review/light-1440x900.png`、`light-1024x800.png`、`light-390x844.png`、`dark-1440x900.png`、`dark-1024x800.png`、`dark-390x844.png`。截图由确定性 E2E fixture 生成，不使用真实 Codex Home 或像素基线。

### 结果与剩余风险

- 默认路径能够在读取完整详情时直接给出可跳转的派生交接结论；读取受限时不会虚构目标、结果、验证或风险。
- 审阅图覆盖三种目标视口和浅深色；移动与窄桌面没有水平溢出断言失败。
- 风险：摘要依赖服务端已提供的 Audit/Trace 派生字段，因此读取失败或文件变化时只能显示可恢复状态，不能替代后续人工复核。改动范围只在可解析的工具变更集合出现时显示文件数。
- 下一步判断：本轮范围已闭环；主 agent 应复查截图中的文字密度及文件变化状态文案，再决定是否需要进一步压缩摘要字段。

## 2026-07-20 第 2 轮

### 审阅问题与修复

- 一级处于“会话”或“复盘”时，`#diagnosticSwitch` 现在同时使用 `hidden`、`inert` 和 `aria-hidden` 退出视觉与焦点序列；进入“诊断”后才显示，并由状态机保证“统计 / 原始事件”恰有一个二级 tab 选中。切出诊断时若焦点仍在二级切换器，会迁移到当前一级入口。
- 交接摘要从标题块移到工具栏的跨列结论区，桌面按实际主栏宽度自动分为两列，窄屏再降为一列。每项正文最多显示三行受控换行，并保留与当前派生摘要一致的 `title` 与 `aria-label`，避免把目标、结果或风险压成数个字；摘要仍只使用首行、最多 180 字的已加载派生数据，带审计节点的项可跳转查看完整证据。
- 821px 至 1280px 保持复核台默认收起。1024x800 按需打开后，复核对象头不再限制为 44px；复核正文是带可访问名称的可聚焦滚动区，键盘触发打开时焦点直接进入该区域，因此对象标题、摘要和后续内容都可自然阅读。
- 新增 `public/evidence-id.js` 作为唯一证据 ID 构造器。ID 固定包含数据源、会话、线程路径或节点、轮次和/或事件索引、对象类型。会话列表、阅读目录、复盘、原始事件和复核对象复用同一规则；根会话和子代理各自的“第 1 轮”不会碰撞。
- README 删除“四个主视图”的过期表述，改为“会话 / 复盘 / 诊断”一级信息架构。

### 验证证据

- `test/evidence-id.test.mjs` 覆盖根会话与子代理在重复“第 1 轮”时生成不同 ID，同一子代理对象保持稳定 ID。
- `test/e2e/frontend-redesign-contract.spec.mjs` 覆盖默认诊断切换器不可见且 inert、诊断态二级 tab 完整语义、1440 摘要两列与可访问全文、跨列表/阅读/复盘/原始事件/复核对象的 ID 一致性，以及 1024 键盘打开后的复核内容焦点和自然标题高度。
- 重新生成审阅截图：`test-results/frontend-redesign-review/light-1440x900.png`、`light-1024x800.png`、`light-390x844.png`、`dark-1440x900.png`、`dark-1024x800.png`、`dark-390x844.png`。

### 保留边界与风险

- 原始事件继续只在诊断分页和复核台“来源”页按需读取；切换视图时的取消、快照隔离、移动面板和减少动画逻辑未改变。
- 摘要可读性依赖已完整读取的详情与 Audit/Trace 派生字段；文件变化时只显示可重新读取的状态。三行视觉上限之外的完整文本可通过焦点、读屏和原生标题取得，不能替代人工复核。

## 2026-07-20 第 3 轮

### 审阅问题与修复

- 截图复查发现 1024x800 的低高度窄桌面规则曾取消 `#sessionDetails` 的高度上限。极长对象标题或摘要会持续撑开上下文区，挤掉复核 tab 与 `#selectionDetails`，无法在同一视口继续复核。
- 821px 至 1280px 的上下文区现在始终保持独立滚动边界；低高度视口上限为 72px，常规窄桌面为 68px。该区保留滚动条空间并隔离 overscroll，正文继续作为主滚动区，因此 tab 和正文有稳定的可见高度预算。
- `#sessionDetails` 现为可聚焦的具名上下文区，`aria-label` 明确其对象语义与键盘滚动方式，并沿用复核正文的可见焦点样式。键盘打开复核台时原有焦点仍进入正文，不会改变鼠标打开、诊断二级入口、原始事件按需读取或取消语义。
- 将新增浏览器模块 `public/evidence-id.js` 纳入 `npm run check` 的 `node --check` 清单。

### 验证证据

- `test/e2e/frontend-redesign-contract.spec.mjs` 使用现有确定性 1000 字符 Chromium 标题，在 1024x800 验证上下文区可聚焦、存在实际溢出、`PageDown` 后滚动位置前进、复核 tab 位于视口内，以及 `#selectionDetails` 至少保留 64px 可用高度。
- 截图测试除页面无水平溢出外，也对 1024x800 的 tab 可见性、正文可用高度和上下文区真实溢出作断言；重新输出浅深色各三张审阅图：`test-results/frontend-redesign-review/light-1440x900.png`、`light-1024x800.png`、`light-390x844.png`、`dark-1440x900.png`、`dark-1024x800.png`、`dark-390x844.png`。
- 已运行 `npm run verify`。

### 保留边界与风险

- 上下文区在窄桌面中有意限制为紧凑高度；完整长标题与摘要通过该区的键盘和鼠标滚动读取，不再以挤压复核正文为代价。极长的连续无空白文本会按既有 `overflow-wrap` 在区内换行。
- 原始事件仍仅在诊断态和复核台“来源”页按需读取；切换视图的取消、快照隔离、诊断二级入口和减少动画均未改动。

## 2026-07-20 第 4 轮

### 需求变更

- 产品明确取消“会话详情超过读取上限”的能力降级。会话、复盘、外部 `compact/turns/trace/audit` view 和 Markdown 必须完整读取，不能因文件大小或事件数显示空正文、`complete: false` 或 `413`。
- 原始事件改为始终可进入的独立分页诊断。它保留单次字节预算、事件扫描预算、最近六页摘要、快照隔离、取消和按需读取完整来源；这些预算不再控制主会话详情。

### 实施与验证

- 服务端移除详情文件字节数和事件数限制，只保留读取闸门、取消、文件签名复核和缓存总预算；文件变化仍返回可重新读取状态，避免旧内容被作为最新内容展示。
- 工作台删除“受限详情切入诊断”的分支。诊断页明确标注独立诊断预算，交接摘要和 Markdown 操作基于完整详情继续可用。
- HTTP smoke 将 10,002 事件夹具改为完整详情、四类外部 view、两条 Markdown 路由都成功的回归；E2E 保留分页缓存、文件变化、取消和来源展开覆盖。
