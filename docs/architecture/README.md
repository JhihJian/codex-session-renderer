# Codex 会话工作台架构

## 目的

Codex 会话工作台是一个只读浏览器。它把 Codex 与 Pi Agent 写入 JSONL 的会话记录投影为会话目录、详情、执行过程、时间统计、原始事件和任务归档，帮助读者理解一次 agent 执行中发生的输入、回复、工具调用和子代理活动。

产品不根据会话记录给出正确性、安全性、风险或缺陷归因结论。原始记录仍是诊断时的事实来源，工作台的摘要和标题只改善阅读与检索。

## 系统边界

系统读取本机 Codex Home、可选 Pi Agent 会话根，以及已发布到本机私有目录的远端 Codex 快照。它绝不改写 Codex 或 Pi Agent 的原始会话文件。

“只读”不表示进程完全没有本地写入：工作台会在用户目录持久化远端连接定义，并在私有快照根写入远端暂存、版本、来源状态和当前快照指针。这些写入不反向同步到会话来源。

主 HTTP 服务默认只监听 loopback。配置为非 loopback 时，静态资源和全部 HTTP 路由都要求令牌认证。远端快照共享是独立服务，只有显式提供 Bearer 令牌才能启动。远端身份供应、TLS 部署、网络隔离、数据保留和备份不由本项目负责。

## 主要责任单元

- [会话读取与投影](modules/session-projection.md)：发现可读会话，建立来源隔离上下文，将 JSONL 和 SQLite 元数据投影为浏览器所需的列表、详情、事件、执行过程、时间统计和 Markdown。
- [任务归档与目标投影](modules/prompt-archive-and-goal-projection.md)：从稳定会话中有界提取首个有效用户任务，并对已验证的 Codex/Pi Goal 控制包失败关闭地投影目标文本。
- [远端快照与共享](modules/remote-snapshot-sharing.md)：管理受保护的远端定义、快照刷新和发布，以及供历史定位使用的受认证索引与快照共享。
- [实现参考](implementation.md)：提供 HTTP 装配、源码入口、运行时配置类别和测试映射；事件字段和兼容 profile 由[事件规范化契约](../session-event-normalization.md)负责。

## 核心流程

### 浏览会话

1. 主服务建立本机、可选 Pi Agent 和远端来源的数据上下文。Pi Agent 会话根可用时成为默认来源，否则使用本机 Codex。
2. 列表优先从 SQLite 线程元数据取得候选并确认对应 JSONL 可读，索引不可用时回退到受限 JSONL 扫描。远端来源只能读取当前、同源且安全的本地快照。
3. 详情在读取前后核验文件签名。稳定文件才会规范化并派生轮次、执行树、统计和 Markdown；文件变化、取消或读取失败不会被缓存或伪装为完整详情。
4. 浏览器只消费投影和按需诊断接口。需要完整原始 payload 时，读者进入 Raw 或单事件接口，而不是从摘要反推事实。

### 归档任务

1. 任务归档从来源和范围确定候选会话，并为每个候选建立独立、可取消的读取订阅。
2. 协调器在固定文件、事件和正文预算内读取首段 JSONL，再次确认签名后提取第一个有效用户任务。
3. 未找到任务、文件变化、超出预算或读取失败都以明确状态返回。受限或变化中的内容不进入归档正文，也不作为缓存结果。

### 刷新远端来源

1. 主服务按配置的来源版本启动一次受共享订阅和全局并发门限约束的刷新。
2. 刷新将远端归档或本地同步目录放入私有暂存区，执行路径、允许文件集、大小、文件数、来源身份和取消检查。
3. 验证通过后才以新的私有代际原子替换 `current`。失败、取消或来源配置改变时不会发布暂存数据，先前的同源可用快照保持可读。
4. 历史会话定位通过共享端索引获取受限元数据，不下载历史正文；读详情前仍必须刷新并发布对应快照。
