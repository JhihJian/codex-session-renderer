# Codex 会话工作台架构

## 目的

Codex 会话工作台把 Codex 和 Pi Agent 的 JSONL 会话记录组织为可浏览的会话、详情、执行过程、统计和原始事件视图。它的目标是帮助读者理解一次 agent 执行中接收的任务、生成的内容、工具调用、子代理和时间投入，而不是对记录作正确性、安全性或风险结论。

## 系统边界

工作台读取本机 Codex Home、可选 Pi Agent 会话目录，以及已发布到本地受保护快照的远端 Codex 数据。原始会话文件不会被修改。浏览器可管理远端数据源定义和请求刷新，但会话内容始终从本地文件或已完成发布的快照读取。

主服务默认只监听 loopback 地址。配置为非 loopback 监听时，所有静态资源和 API 都要求访问令牌。快照共享服务是单独的 HTTP 服务，只有配置令牌后才会启动，且其三个端点均要求 Bearer 令牌。

## 主要责任单元

- [会话读取与投影](modules/session-projection.md)：发现会话文件和 SQLite 线程，解析、规范化并投影为列表、详情、查询和导出所需的数据。
- [远端快照与共享](modules/remote-snapshot-sharing.md)：管理远端定义，将符合允许文件集和资源限制的内容发布为私有本地快照，并提供受保护的共享端点。
- [实现参考](implementation.md)：列出 HTTP 装配、数据源、会话投影和浏览器界面的精确实现入口。

## 核心流程

1. 主服务加载数据源注册表，创建本机、远端和可选 Pi Agent 来源的读取上下文。
2. 会话列表先使用 SQLite 线程索引；索引不可用或不能覆盖时，再在已验证的 JSONL 根目录中发现会话。详情读取由并发协调器保护，并在读取期间检查文件是否变化。
3. JSONL 事件被统一规范化后聚合为轮次、工具调用、时间线、子代理层级和查询投影；浏览器从 HTTP API 获取这些投影或静态资源。
4. 远端来源刷新时先下载或复制到私有暂存目录，验证快照内容和来源身份，再原子发布为当前版本。任何失败保留上一个可用快照并向调用方返回受控错误。

## 阅读路径

先阅读本总览了解边界和协作关系，再按任务进入会话投影或远端快照模块。需要精确 API 路由、环境变量和实现定位时阅读实现参考。
