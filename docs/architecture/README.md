# Codex 会话工作台架构

## 目的

Codex 会话工作台把 Codex、Pi Agent 与已识别的 Claude Code JSONL 会话记录投影为会话目录、详情、执行过程、时间统计、原始事件和面向 agent 分析的执行文本，帮助读者先连续理解一次 agent 执行中发生的输入、回复、工具调用和子代理活动，再按需追溯其执行细节。

摘要、标题和统计服务于阅读与检索，原始记录保留为诊断事实来源。会话内容的正确性、安全性、风险和缺陷归因由会话外的证据与审查流程判断。

## 系统边界

系统读取本机 Codex Home 与可选 Pi Agent 会话根。文件位置决定读取权限和来源身份，格式适配器决定事件解释方式；原始会话文件保持不变，工具返回结果以其中已持久化的内容为界，输出内指向的临时文件不属于会话来源，服务不会读取它来补全内容。服务可写自身的运行时配置文件（Pi 会话读取根覆盖），除此之外不写任何会话相关文件。执行文本仅使用白名单字段，工具输出只用于计算已持久化的 UTF-8 字节数和截断状态，不写入导出正文。主 HTTP 服务默认只监听 loopback；非 loopback 监听要求令牌认证，配置写接口沿用同一认证且仅接受 JSON 请求。

## 主要责任单元

- [会话读取与投影](modules/session-projection.md)：发现本机 Codex 与 Pi Agent 会话，建立来源隔离上下文，按会话格式适配 JSONL 和 SQLite 元数据，投影为浏览器所需的列表、详情、事件、执行过程、时间统计和 Markdown。

- [实现参考](implementation.md)：提供 HTTP 装配、源码入口、运行时配置类别和测试映射；事件字段和兼容 profile 由[事件规范化契约](../session-event-normalization.md)负责。

## 核心流程

### 浏览会话

1. 主服务建立本机 Codex 与可选 Pi Agent 的数据上下文。Pi Agent 会话根可用时成为默认来源，否则使用本机 Codex。设置 `CODEX_SESSION_RENDERER_CONFIG_PATH` 后，操作者可在设置界面的数据源页保存单个 Pi 根覆盖：服务校验后原子写入配置文件，整体重建数据源注册表并清空来源缓存，在途请求持旧上下文自然结束；清除覆盖即回到环境变量默认。
2. 会话模块从可读来源建立目录，并将单次读取结果派生为详情、执行过程、统计。会话文件在读取中追加时，本次响应保持已读取结果；文件更新后下一次详情请求重新读取。
3. 浏览器以工作目录树中的会话叶子和正文构成默认阅读面，并在同一主工作区提供正文、执行、诊断三个互斥视图。目录折叠状态只属于当前浏览器会话，搜索结果自动展开，当前会话所在目录也可由用户折叠且在重新渲染后保持；正文只把持久化 JSONL 可证明的压缩和 Skill 指令/读取证据投影为上下文事件，执行、统计、Raw 与单事件接口只在对应视图中消费，避免常驻挤压阅读空间。执行视图可经来源化只读接口下载独立的执行文本，浏览器不从 DOM 重组导出内容。
