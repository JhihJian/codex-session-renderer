# Codex 会话工作台架构

## 目的

Codex 会话工作台把 Codex 与 Pi Agent 写入 JSONL 的会话记录投影为会话目录、详情、执行过程、时间统计和原始事件，帮助读者先连续理解一次 agent 执行中发生的输入、回复、工具调用和子代理活动，再按需追溯其执行细节。

摘要、标题和统计服务于阅读与检索，原始记录保留为诊断事实来源。会话内容的正确性、安全性、风险和缺陷归因由会话外的证据与审查流程判断。

## 系统边界

系统读取本机 Codex Home、可选 Pi Agent 会话根，以及已发布到本机私有目录的远端 Codex 快照。原始会话文件保持不变。

远端连接定义和远端快照属于工作台的本地派生状态，与会话来源隔离。主 HTTP 服务默认只监听 loopback；非 loopback 监听要求令牌认证。快照共享服务独立运行并要求令牌认证。

远端身份供应、TLS 部署、网络隔离、数据保留和备份由运行环境负责。

## 主要责任单元

- [会话读取与投影](modules/session-projection.md)：发现本机 Codex 与 Pi Agent 会话，建立来源隔离上下文，将 JSONL 和 SQLite 元数据投影为浏览器所需的列表、详情、事件、执行过程、时间统计和 Markdown。

- [实现参考](implementation.md)：提供 HTTP 装配、源码入口、运行时配置类别和测试映射；事件字段和兼容 profile 由[事件规范化契约](../session-event-normalization.md)负责。

## 核心流程

### 浏览会话

1. 主服务建立本机 Codex 与可选 Pi Agent 的数据上下文。Pi Agent 会话根可用时成为默认来源，否则使用本机 Codex。
2. 会话模块从可读来源建立目录，并将稳定会话派生为详情、执行过程、统计。变化中的会话返回明确读取状态。
3. 浏览器以工作目录树中的会话叶子和正文构成默认阅读面，并在同一主工作区提供正文、执行、诊断三个互斥视图。目录折叠状态只属于当前浏览器会话，搜索和当前会话路径自动展开；正文只把持久化 JSONL 可证明的压缩和 Skill 指令/读取证据投影为上下文事件，执行、统计、Raw 与单事件接口只在对应视图中消费，避免常驻挤压阅读空间。
