# 任务归档与目标投影

## 设计结论

任务归档将“首个有效用户任务”作为独立的有界读取投影，而不是从会话标题猜测。Goal 控制包只在已验证的 Codex 或 Pi 协议结构完整时投影其中的用户目标；任何未知、损坏或不匹配的包均失败关闭，保持普通原始消息语义。

## 要解决的问题

会话的首个可见用户文本可能包含机器上下文、事件回声、fork replay、自动续跑指令或 Goal 控制规则。归档需要批量读取候选会话，但不能因大文件、频繁变化或取消而泄露不完整文本、耗尽读取资源或缓存旧版本。

## 核心模型

- 归档身份由 `sourceId + sessionId` 组成，项目分组由 `sourceId + cwd` 组成。会话标题不是提示词缺失时的回退正文。
- 协调器在读取前后比较文件签名，以签名为 in-flight 共享、缓存和失效边界。每个 HTTP 请求是独立订阅，取消一个订阅不会终止仍有订阅者的同次读取。
- 归档只在固定的文件大小、事件条数、并发、会话数和正文长度预算中提取第一个有效用户任务。超限、变化、不可用和错误拥有明确状态，敏感正文不会进入响应或缓存。
- Goal 投影器维护每个事件流的协议状态。它只接受当前实证的 Pi 会话版本和 Codex `thread_goal_updated` 关联结构，并要求目标、父子关系、计数、时间、UUID 和完整控制模板一致。

## 与现有模块的交互

会话读取模块提供经过来源隔离和路径验证的候选及读取闸门。归档模块复用事件构建规则提取用户任务，Goal 投影结果同时服务于阅读、标题、搜索和 Markdown。原始事件及单事件诊断仍由会话读取模块提供，始终保留控制包的完整 JSON。

## 必须保持的规则

- 自动 Goal 控制规则、续跑 marker、预算和目标 ID 不得混入默认阅读、任务归档、Markdown 或语义搜索；只有经验证的 objective 可以进入这些投影。
- 原始事件、按需 Raw 和单事件接口必须保留控制包，不得因为默认投影而删除诊断事实。
- 文件变化、取消和读取异常不得生成归档缓存。超出任一归档预算时，不得返回部分正文。
- 相同的稳定会话版本可合并读取；同一来源与会话的新文件签名必须使旧缓存失效。

## 交付边界

模块不声称 JSONL 是密码学可信输入，也不承诺未知 Codex、Pi 或 Goal 扩展版本的兼容性。支持的 profile、严格模板和字段级兼容规则由[事件规范化契约](../../session-event-normalization.md)负责。

## 实现定位

- `src/prompt-archive-coordinator.mjs` 实现预算、并发、共享订阅、取消、签名验证和缓存。
- `src/session-prompts.mjs` 从规范化轮次提取并构造归档条目。
- `src/pi-goal-projection.mjs` 实现 Codex/Pi Goal 的严格状态机与失败关闭投影。
- `server.mjs` 负责候选分页、归档接口和对浏览器断开的取消传播。
