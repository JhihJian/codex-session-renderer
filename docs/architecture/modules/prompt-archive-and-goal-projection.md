# 任务归档与目标投影

## 设计结论

任务归档将“首个有效用户任务”作为独立的有界读取投影。Goal 控制包通过受支持 profile 的结构验证后，才将其中的用户目标写入默认投影；其余记录保持原始消息语义。

## 要解决的问题

会话的首个可见用户文本可能包含机器上下文、事件回声、fork replay、自动续跑指令或 Goal 控制规则。归档以文件、事件、正文和并发预算批量读取候选会话，并只将稳定版本的有效任务写入响应与缓存。

## 核心模型

- 归档身份由 `sourceId + sessionId` 组成，项目分组由 `sourceId + cwd` 组成。提示词缺失时使用归档状态表达结果。
- 协调器在读取前后比较文件签名，以签名为 in-flight 共享、缓存和失效边界。每个 HTTP 请求拥有独立订阅，订阅者集合决定底层读取是否继续。
- 归档在固定的文件大小、事件条数、并发、会话数和正文长度预算中提取第一个有效用户任务。超限、变化、不可用和错误均有明确状态；正文仅随成功归档结果返回和缓存。
- Goal 投影器维护每个事件流的协议状态，并向默认投影写入通过结构验证的受支持控制包目标。profile、字段条件和模板由[事件规范化契约](../../session-event-normalization.md)唯一负责。

## 与现有模块的交互

会话读取模块提供经过来源隔离和路径验证的候选及读取闸门。归档模块复用事件构建规则提取用户任务，Goal 投影结果同时服务于阅读、标题、搜索和 Markdown。原始事件及单事件诊断仍由会话读取模块提供，始终保留控制包的完整 JSON。

## 必须保持的规则

- 默认阅读、任务归档、Markdown 和语义搜索只投影经验证的 objective，不包含 Goal 控制规则、续跑 marker、预算和目标 ID。
- 原始事件、按需 Raw 和单事件接口保留完整控制包，作为诊断事实来源。
- 归档缓存只接受稳定文件版本；超出任一归档预算时以受限状态返回。
- 相同的稳定会话版本可合并读取；同一来源与会话的新文件签名必须使旧缓存失效。

## 交付边界

JSONL 的可信性边界由结构验证确定。支持的 profile、严格模板和字段级兼容规则由[事件规范化契约](../../session-event-normalization.md)负责。

## 实现定位

- `src/prompt-archive-coordinator.mjs` 实现预算、并发、共享订阅、取消、签名验证和缓存。
- `src/session-prompts.mjs` 从规范化轮次提取并构造归档条目。
- `src/pi-goal-projection.mjs` 实现 Codex/Pi Goal 的严格状态机与失败关闭投影。
- `server.mjs` 负责候选分页、归档接口和对浏览器断开的取消传播。
