# 远端快照与共享

## 设计结论

远端会话不会直接暴露给浏览器或主服务的会话读取路径。模块先把远端内容放入私有暂存目录，验证来源身份、归档结构、允许文件集和资源预算后，才原子发布为当前本地快照。共享端以独立 HTTP 服务提供同样受限的快照归档和历史索引。

## 要解决的问题

远端会话可在传输期间改变，也可能包含超限、越界或未允许内容。远端地址变更后，旧快照不能继续代表新来源。工作台还需要在不下载历史正文的前提下定位较早会话，并确保共享服务不会在无认证时泄露记录。

## 核心模型

- 本机配置存储持有可公开的连接元数据与仅本地保存的令牌；令牌不会进入浏览器来源响应、日志错误或快照元数据。
- 每个远端定义计算来源版本，并拥有自己的私有快照根。当前快照的来源证明必须匹配该版本，否则来源处于需要刷新状态而不可读取。
- 刷新操作按“共享订阅、并发闸门、私有暂存、验证、代际发布、清理”的顺序执行。发布时在快照根的提交协调器内做最终来源检查和 `current` 指针替换。
- 快照只允许会话 JSONL、线程数据库、会话索引和产品元数据。归档解压还限制路径类型、重复路径、传输/解压字节数和文件数。
- 共享服务单独认证健康、归档和索引端点。索引优先受限 SQLite 查询，不能使用时才扫描受预算限制的文件，并返回不含历史正文的紧凑会话元数据。

## 与现有模块的交互

主服务通过数据源注册表刷新并切换远端来源，通过受期限和取消信号保护的 HTTP 客户端访问共享服务。会话读取模块只消费通过来源围栏的 `current` 快照。任务归档模块只能读取该快照中已经可读的会话，不能把历史索引条目当作可读取正文。

## 必须保持的规则

- 暂存、验证、取消或来源版本变化期间，绝不替换当前快照。刷新失败不破坏仍与当前来源匹配的既有快照。
- 快照必须拒绝不允许的文件、符号链接、不安全或重复归档路径，以及超出传输、解压、文件数、队列或时间预算的内容。
- 当前快照的来源证明与配置来源版本不一致时，旧快照不可读，必须完成新刷新。
- Unix 上远端配置、快照目录和快照文件分别收紧为私有权限。令牌不返回浏览器，也要从面向用户的错误中脱敏。
- 快照共享服务缺少令牌时不得启动；每个共享端点均要求匹配的 Bearer 令牌。

## 交付边界

模块负责受限传输、本地私有发布和共享接口，不负责远端账户身份供应、TLS 终止、网络拓扑、数据保留或备份策略。浏览器不会直接配置任意文件路径，也不能读取远端历史会话正文。

## 实现定位

- `src/renderer-config.mjs` 管理私有远端连接定义与公开视图。
- `src/data-sources.mjs` 负责来源版本、刷新、归档验证、私有权限和快照发布。
- `src/remote-http.mjs`、`src/snapshot-budget.mjs` 与 `src/snapshot-root-commit-coordinator.mjs` 提供传输取消、资源预算和原子提交协作。
- `share-server.mjs` 与 `src/snapshot-share.mjs` 装配并实现受认证的共享端点，`src/remote-session-index.mjs` 负责历史索引文件回退。
