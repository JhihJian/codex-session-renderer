# 会话读取与投影

## 设计结论

会话读取采用“来源上下文 + 可验证文件读取 + 纯投影”的设计。`server.mjs` 负责把 HTTP 请求编排到当前数据源上下文，`src/` 中的读取、规范化、查询和展示模型模块将原始 JSONL 与 SQLite 记录转换为稳定的 API 数据，而不改写原始会话。

## 要解决的问题

Codex 与 Pi Agent 的会话来源、事件格式和可用索引不同，且正在写入的 JSONL 文件可能在读取期间变化。调用方需要会话目录、详情、事件页、执行过程和 Markdown 导出，同时不能把错误路径或未完成读取伪装成完整内容。

## 核心模型

- 数据源上下文持有来源身份、会话根、线程数据库、缓存和详情读取协调器。远端上下文只能读取当前且可用的本地快照。
- 会话目录优先使用 SQLite 线程索引，并以 JSONL 元数据补全；文件扫描是索引缺失或不适用时的后备路径。
- 规范化器从原始事件提取角色、文本、工具输入输出、推理摘要、附件和时间字段。后续模块按需要生成轮次、查询结果、时间线和子代理树。
- 详情协调器限制并发读取、合并等价读取请求，并在读取前后比较文件签名。变化中的文件以明确读取状态返回，而不是缓存为稳定详情。

## 与现有模块的交互

HTTP 路由根据 `sourceId` 选择数据源上下文，再调用列表、查询、详情、单事件或 Markdown 投影。会话投影依赖数据源模块提供可读路径和来源状态，依赖 `http-response` 输出受控响应；它不负责远端下载、浏览器状态或访问控制策略。

## 必须保持的规则

- 原始 Codex 与 Pi Agent 会话文件只读，所有展示和导出都基于读取结果。
- 远端会话路径必须位于已发布快照的允许根中，不能以来源记录中的任意路径直接读取。
- 详情读取前后文件签名不一致时，不得将结果作为完整会话详情返回。
- 规范化和查询投影必须保留来源身份，避免不同远端或本地同名会话相互混淆。

## 交付边界

本模块提供会话的发现、读取和投影，不负责判断会话内容的事实性、风险或缺陷归因。浏览器的布局、筛选交互和呈现细节由 `public/` 负责。

## 实现定位

- `server.mjs` 中的 `listSessions`、`getSessionDetail` 和路由处理负责请求级编排。
- `src/session-normalizer.mjs` 中的 `normalizeSessionEvent` 统一原始事件结构。
- `src/session-detail-coordinator.mjs` 管理详情读取并发、共享订阅和缓存。
- `src/session-query.mjs` 解析查询参数并过滤、排序和投影会话与事件。
