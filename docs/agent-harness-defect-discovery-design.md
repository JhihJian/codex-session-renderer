# Agent Harness 缺陷发现与验证体系设计

## 1. 目标与边界

本体系将本机沉淀的 Pi Agent JSONL 会话转化为一份**可复现验证的 Agent Harness 缺陷列表**。最终列表中的每个缺陷都必须能在隔离环境中由自动化断言复现，并能说明它属于 Pi 核心、Pi 与扩展的集成、工具适配层，还是外部依赖。

历史会话的角色是发现线索与保存事实证据，不能单独证明缺陷。模型的自然语言结论、用户的抱怨、单次工具失败、会话标题中的错误词，都只能构成候选信号。

本设计覆盖：

- 会话原件归档、完整性、脱敏和访问边界；
- 会话树与上下文投影的离线校验；
- 从历史证据发现、去重和分诊候选；
- 隔离回放、单因素对照和版本差分；
- 缺陷准入、回归测试、关闭与归档。

本设计不覆盖：

- 评估某个模型“是否足够聪明”；
- 自动为候选创建外部 issue 或将责任归属给个人；
- 在真实项目目录、真实凭据或生产服务上回放；
- 以历史会话内容训练或外发模型。

## 2. 成功定义

一条记录进入 `confirmed` 缺陷列表时，必须同时具备：

1. **失败谓词**：可由程序或固定审计规程判定的布尔事实 `F`，例如“取消后的工具仍被执行一次”，而不是“结果看起来不对”。
2. **最小夹具**：不含真实密钥、业务数据和用户代码的输入、工具替身、环境清单及执行命令。
3. **对照证据**：在输入、环境、模型响应和扩展条件相同的情况下，只有被测 harness 版本或配置变化时 `F` 的结果发生变化。
4. **稳定复现**：确定性问题在独立临时目录中连续 3 次均满足断言；竞态或概率性问题使用预登记的运行次数和阈值，保存每次调度轨迹。
5. **归因结论**：能够排除模型随机性、用户输入歧义、项目环境、工具服务和不合规扩展，或明确将其归入相应非核心类别。
6. **回归保护**：缺陷修复版本具有可运行的测试，并记录受影响、首次修复和已验证的 Pi 版本。

## 3. 总体架构

```text
Pi JSONL 原件 ──> 归档器 ──> 原始证据库（私有、不可变）
                         │
                         ├──> 脱敏派生索引 ──> 候选检测器 ──> 分诊队列
                         │                                      │
                         │                                      v
现有工作台 <──────────────┘                              复现夹具生成
  （只读复核）                                                   │
                                                               v
                                         隔离回放器 <──> 固定 provider / 工具替身
                                                               │
                                                               v
                                           对照与版本差分 <──> 缺陷库与回归集
```

`codex-session-renderer` 保持为只读的会话浏览、候选定位和证据复核入口。原件存储、脱敏索引、回放工作目录和实验结果必须位于仓库外的受限目录，不能被 HTTP 会话浏览接口直接提供，也不能提交到 Git。

## 4. 数据与安全边界

### 4.1 三层证据模型

| 层级 | 内容 | 访问与用途 |
| --- | --- | --- |
| 原始证据库 | 字节级 JSONL 快照、来源路径映射、完整性清单 | 最小人数访问，仅用于核验与受控取证 |
| 脱敏分析库 | 规范化事件、结构特征、哈希、伪名和最小文本片段 | 候选检测、统计、工作台复核 |
| 复现证据包 | 合成输入、fixture、固定响应、环境 manifest、断言结果 | 共享、回归和缺陷报告 |

原始会话可包含用户提示、代码、命令输出、绝对路径、图片 base64、thinking、扩展 `details`、访问令牌和连接串。原件默认按受限数据处理，不能使用 Pi 的 `/share`、HTML 导出或普通网盘作为原件传播途径。

### 4.2 归档协议

归档器只读扫描 `~/.pi/agent/sessions/**/*.jsonl`，对每个文件执行：

1. 在读取前记录 `(path, size, mtime, ctime)`；
2. 流式复制到临时位置，同时计算 `SHA-256`；
3. 再次获取文件签名；两次签名不一致则删除临时副本、标记 `changing` 并延迟重试；
4. 对稳定副本生成只追加的 `archive-manifest.jsonl`；
5. 将副本设为只读，并以当前用户私有权限保存。需要跨用户保存时，采用受组织密钥管理保护的加密存储。

manifest 至少包含 `archiveId`、原路径的不可逆别名、会话 ID、归档时间、字节数、SHA-256、Pi/Node/OS 版本、采集器版本、来源状态和保留状态。原路径映射属于原件库，不进入分析库。

### 4.3 脱敏与共享闸门

脱敏器遍历所有字段，不能只处理正文。覆盖范围包括 `cwd`、`parentSession`、会话名、用户/助手消息、thinking、工具参数与结果、`bash.command`/`output`、`details`、`custom.data`、摘要、图片和完整输出路径。

- 每个证据包使用独立 HMAC 密钥伪名化项目、路径、主机和标识符，以保留同包关联而不建立跨案件关联。
- 扫描先识别密钥、私钥、JWT、连接串、个人信息和高熵疑似凭据，再对脱敏结果做第二次扫描。
- 发现疑似有效凭据时先按安全事件处理和轮换，不把“已经遮盖”视为风险已经消失。
- 解析失败、未知 schema、未知扩展字段或二次扫描命中时，证据包不得自动共享，进入人工复核。
- 默认不保留和共享 thinking 全文、图片、源代码副本和完整工具输出。复现包优先以合成数据和受控工具响应替代。

保留期限应由数据所有者确认。在获得正式策略前，未分诊原件应采用短保留、可审计删除；已立案证据仅保留到回归夹具与复核结论稳定为止。

## 5. 规范化与会话图

Pi 会话是 `id`/`parentId` 构成的树，不能按 JSONL 文件行号直接当作一次线性对话。分析的最小单位是：

```text
SessionGraph + LeafId + BranchProjection
```

`SessionGraph` 保存所有原始条目、物理行号、父子关系、重复 ID、孤儿节点、环、会话版本和解析诊断。`BranchProjection` 针对一个叶节点，按 Pi `buildContextEntries()` 的语义产生：活跃路径、压缩边界、`firstKeptEntryId`、分支摘要、进入模型上下文的消息、有效模型和 thinking 设置。

实现投影器时，必须与 Pi v1-v3 兼容，并使用固定 fixture 对照 Pi `SessionManager` 的以下语义：

- 压缩只以摘要和 `firstKeptEntryId` 之后的内容替代旧上下文；
- 工具结果不能被切在其工具调用之外；
- 分支摘要是切换分支后的附加上下文，不能当作原路径事件；
- `custom` 不进入模型上下文，`custom_message` 会进入；
- 模型和 thinking 使用活跃路径的最后有效设置。

解析异常、截断文件和旧格式迁移只产生“数据质量/兼容性候选”，除非可以在受控 Pi 版本上证明保存或加载行为违反公开契约。

## 6. 候选发现与分诊

候选检测分为确定性校验和行为模式两层。每条规则都有版本、前置条件、失败谓词、误报排除条件、严重性指南和证据坐标；文本关键字只能用于排序，不能单独触发确认。

| 类别 | 可检测的不变量或模式 | 历史会话不足时的处理 |
| --- | --- | --- |
| 会话持久化 | ID 唯一性、父节点存在性、压缩边界、分支投影一致性 | 保留结构候选 |
| 上下文正确性 | 投影遗漏、重复消息、错误模型/思考设置继承 | 用离线 L0 重建验证 |
| 工具协议 | tool call/result 配对、重复执行、结果错配、错误标记丢失 | 用受控工具 L1 验证 |
| 控制流 | 取消后继续执行、队列错投、自动重试边界、终止条件 | 历史缺少运行事件时标记观测不足 |
| 扩展边界 | `tool_call` 变更未传递、扩展状态跨分支泄漏、生命周期顺序错误 | 显式加入扩展开关对照 |
| 安全与资源 | 未截断输出、敏感值进入非受限视图、超过边界后仍读写 | 使用合成大输入验证 |

候选状态只能是：`new`、`triaged`、`reproducing`、`confirmed`、`rejected`、`external`。`external` 用于模型、项目环境、provider 或扩展自身的问题。只有 `confirmed` 出现在正式缺陷列表。

每张候选证据卡在实验前冻结以下内容：候选 ID、规则版本、原始 archive ID 与事件坐标、失败谓词 `F`、最小触发描述、预期不变量、环境已知项与未知项、预登记的样本量及成功阈值。实验完成前不得按结果修改 `F` 或阈值。

## 7. 新会话运行时遥测

历史 JSONL 记录的是持久化结果，不能完整还原队列变化、流式更新、重试和工具执行时序。从体系启用后，新的实验与抽样运行必须同时保留 Pi 的 `--mode json` 事件流，并与会话归档 ID 关联。

必要事件包括：

- `queue_update`：steering 与 follow-up 队列的变化；
- `compaction_start`/`compaction_end`：原因、是否中止及是否重试；
- `auto_retry_start`/`auto_retry_end`：尝试次数、延迟和结果；
- `agent_*`、`turn_*`、`message_*`：完整生命周期；
- `tool_execution_*`：调用 ID、参数、部分结果、结束与错误状态。

事件流写入独立的实验工件，不回写或修改原始 JSONL。对已有会话，缺少这些事件必须是证据卡的显式限制，不能用事后推测补齐时间顺序。

## 8. 隔离复现与对照实验

### 8.1 复现实验环境

每次实验在新的临时目录运行，使用独立的 `HOME`、`PI_CODING_AGENT_DIR`、`PI_CODING_AGENT_SESSION_DIR` 与工作目录。默认禁用用户全局配置、项目扩展、真实凭据、网络和真实项目目录；只加载明确列入实验 manifest 的 Pi 版本、扩展和 fixture。

实验环境必须记录：Pi 二进制及包哈希、Node 与 OS、依赖锁定哈希、环境变量白名单、输入/输出哈希、provider 和工具替身版本、时钟策略、随机种子、执行命令及完整 JSON 事件流。

工具替身必须是确定性的，并记录调用次数、参数、返回顺序和是否在取消后收到调用。模型端优先使用脚本化 provider：对指定请求序列返回固定文本、工具调用或错误，不以真实模型的非确定性输出作为机械缺陷的主证据。

### 8.2 三层验证

| 层级 | 目的 | 依赖 |
| --- | --- | --- |
| L0 离线重建 | 校验 JSONL 结构、会话图和上下文投影 | 原件副本与纯函数，不运行 agent |
| L1 确定性回放 | 验证控制流、工具、压缩与扩展不变量 | 脚本化 provider、工具替身、虚拟/可控时钟 |
| L2 差分与稳健性 | 判断版本、模型、环境、指令和扩展的归因 | 冻结环境 capsule 与单因素矩阵 |

### 8.3 因果矩阵

令失败谓词为 `F`，唯一主因变量是 harness `H`。所有比较必须固定其他变量：

| 因子 | 对照 | 变化值 | 用途 |
| --- | --- | --- | --- |
| `H` harness | 参考/修复版本 | 被测版本或开关 | 证明主因果效应 |
| `M` 模型 | 脚本化或固定模型配置 | 独立模型分层 | 排除模型特异性 |
| `E` 环境 | 干净冻结 capsule | 第二个受控项目快照 | 排除依赖与工作区状态 |
| `U` 指令 | 最小合法任务 | 语义等价改写 | 排除歧义和措辞依赖 |
| `X` 扩展 | 无扩展/参考实现 | 被测扩展 | 分离扩展和框架集成 |

L1 对决定性不变量至少执行 `H x X`。L2 对已观察到差异的组合扩展 `M`、`E`、`U` 分层，且一次实验只改变一个已登记因素。真实模型实验仅用于验证稳健性，不能取代脚本化 provider 的因果验证。

### 8.4 准入与驳回

确定性问题：被测组合连续 3/3 触发 `F`，参考组合 3/3 不触发，且 L0/L1 证据能定位违反的不变量。

竞态或概率性问题：在预登记的样本量内报告 `P(F)`、调度轨迹和置信区间；缺陷卡必须说明阈值为何能证明工程风险。推荐的强证据门槛是被测组合至少 100 次中 99 次触发、参考组合 100 次中 0 次触发。真实 agent 的稳健性实验应单独报告，不能与确定性比例混合。

出现以下任一情况时，候选不得确认：

- 参考 harness 同样失败，或 `H` 的差异不稳定；
- 仅在单一未固定模型响应、单一项目脏状态、网络或权限条件下出现；
- 关闭被测扩展后消失，且扩展违反其声明或 Pi 公开工具协议；
- 失败谓词只能由主观阅读判断；
- 缺少输入、版本、环境或原始事件定位。

## 9. 缺陷记录与回归集

正式缺陷使用以下最小结构：

```yaml
id: PIH-0001
title: 取消后旧工具调用仍在当前会话执行
category: control-flow
status: confirmed
affected:
  pi: ["0.x.y"]
fixed_in: "0.x.z"
predicate: no_tool_execution_after_cancel
reproduction:
  fixture: fixtures/PIH-0001
  command: npm run reproduce -- PIH-0001
expected: cancel 后工具替身调用次数为 0
actual: cancel 后工具替身调用次数为 1
evidence:
  archive_ids: [redacted-archive-id]
  event_hashes: [sha256:...]
  experiment_runs: [run-...]
attribution: pi-core
regression_test: test/harness/PIH-0001.test.mjs
```

缺陷报告只引用脱敏证据包和哈希。它应描述用户影响、触发前置条件、受影响范围、缓解措施和回归结果，不复制原始会话正文。

回归集按缺陷 ID 存放合成 fixture。每次 Pi 升级或本地 harness 改动后，先执行 L0/L1 全量回归，再挑选高风险缺陷执行 L2 稳健性检查。失败实验本身也是不可变工件，但不自动覆盖旧结论；需要新证据卡说明为何重新分诊。

## 10. 当前项目的模块边界

现有 `src/jsonl-reader.mjs`、`src/session-normalizer.mjs`、`src/session-detail-coordinator.mjs`、`src/audit-chain.mjs` 和事件规范化测试可以复用于只读读取、定位和展示验证。它们不应直接成为确认缺陷的裁决器。

建议新增独立边界，而不是把副作用能力塞入 `server.mjs`：

| 边界 | 职责 | 禁止事项 |
| --- | --- | --- |
| `archive` | 稳定快照、manifest、权限与保留 | 不解析后执行、不提供 HTTP 原件下载 |
| `redaction` | 字段遍历、伪名化、双重扫描、共享闸门 | 不保存明文映射到分析库 |
| `projection` | SessionGraph、BranchProjection、格式不变量 | 不使用展示层摘要替代原始事件 |
| `detectors` | 候选规则、去重、证据卡生成 | 不将启发式直接标为缺陷 |
| `replay` | 隔离进程、fixture provider、工具替身、工件采集 | 不加载用户全局扩展或真实项目 |
| `experiments` | 矩阵执行、对照统计、版本差分 | 不在结果后修改预登记阈值 |
| `registry` | 缺陷状态、证据引用、回归集索引 | 不保存原件正文 |

## 11. 未知项与失效信号

| 未知项 | 当前保守假设 | 验证动作 | 失效信号 |
| --- | --- | --- | --- |
| 历史会话是否含凭据或个人信息 | 按高敏感处理 | 在隔离环境执行脱敏扫描并审计命中类别 | 发现疑似有效凭据，停止共享并触发轮换 |
| 需要验证的 Pi 版本集合 | 先固定当前版本和一个相邻版本 | 记录 `pi --version`、包哈希和变更日志 | 无法获得旧版本，禁止做版本归因 |
| 能否脚本化所有 provider 行为 | 机械缺陷必须能脚本化 | 实现最小 fake provider 协议并用已知 fixture 验证 | 只能依赖真实模型，降级为观察性候选 |
| 队列/取消是否可从现有记录确认 | 不能 | 为新运行采集 `--mode json` 事件流 | 历史没有时序事件，不确认控制流缺陷 |
| 本机存储隔离是否足够 | 先限制到当前用户与私有目录 | 核验权限、备份和磁盘加密策略 | 多用户可读或备份外发，暂停原件归档 |

## 12. 设计验收

体系具备以下能力时，才算设计落地：

- 任一原件能证明来源、字节完整性、读取稳定性和访问边界；
- 任一叶节点可稳定重建其应进入模型的上下文投影；
- 任一候选能定位到原始证据坐标、规则版本和明确失败谓词；
- 任一确认缺陷可从独立临时目录运行，且仅依赖公开的脱敏证据包；
- 确认结论有对照结果、归因、受影响版本和自动化回归测试；
- 工作台只展示允许范围内的派生数据，无法通过 UI 或 API 下载原件；
- 无法满足以上条件的记录仍保留为候选或外部问题，而不进入缺陷列表。
