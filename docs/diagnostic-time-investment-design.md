# 诊断界面时间投入展示设计

## 1. 设计目标

诊断界面增加会话时间投入分析，帮助用户快速回答三个问题：

1. 整个会话持续了多久？
2. 时间主要投入在工具、子代理、委派等待还是系统处理？
3. 每项时间的可信度如何，能否回到具体轮次和原始事件？

时间分析服务于会话复盘。它将会话的墙钟时间、可关联的执行区间、并行关系和时间数据质量放在同一信息结构中，使统计结果能够回到原始会话过程。

## 2. 现状与设计约束

当前页面的导航结构为：

```text
会话
复盘
诊断
├── 统计
└── 原始事件
```

现有 Trace 已经为根会话、轮次、工具和子代理提供 `timestamp`、`completedAt`、`durationMs` 等字段。部分节点的结束时间来自最后事件、文件更新时间或父会话通知，属于估算值。父会话、工具和子代理还可能并行执行，因此节点耗时累加值用于表示执行量，会话墙钟时长则使用时间区间覆盖计算。

设计采用以下口径：

- 会话总时长使用墙钟时间，表示会话首个有效时间点到最后有效时间点的区间。
- 分类时长使用时间区间覆盖，保留节点时长累加值和并行重叠信息。
- 估算、部分区间和缺失关联都带有明确状态。
- 时间分析由服务端统一派生，前端负责展示和跳转。
- 统计筛选只影响明细展示，不改变完整会话的时间口径。

## 3. 页面信息架构

“诊断 → 统计”页面在现有事件类型统计前增加“会话时间”区域：

```text
诊断 / 统计
├── 会话时间概览
├── 时间投入到哪里
├── 按轮次查看
├── 时间数据质量
└── 事件类型统计
```

“诊断 → 原始事件”继续提供分页浏览和单事件回读。时间分析中的每个项目通过 Audit 节点或事件索引回到对应证据。

“复盘”继续负责按轮次查看目标、执行链、证据、验证和风险。时间分析不复制复盘内容，只提供时间视角和跳转入口。

## 4. 会话时间概览

概览使用四个核心指标：

| 指标 | 定义 | 展示示例 |
| --- | --- | --- |
| 总墙钟时长 | 会话首个有效时间点到最后有效时间点的时间差 | `18 分 42 秒` |
| 可解释执行时长 | 已关联到执行节点的时间区间并集 | `14 分 08 秒` |
| 时间覆盖率 | 可解释执行时长 / 总墙钟时长 | `75.7%` |
| 并行峰值 | 同一时间点同时存在的最大执行区间数 | `3 路并行` |

概览下方显示统一口径和可信度，例如：

```text
总时长 18 分 42 秒 · 墙钟时间 · 估算
```

可信度分为：

- `实测`：开始和结束时间均来自可靠事件。
- `混合`：实测区间和估算区间同时存在。
- `估算`：主要依赖首末事件、更新时间或关联通知推导。
- `未记录`：缺少足够时间信息。

## 5. 时间投入分布

时间分布使用横向条和明细表，按覆盖时长降序排列。每个分类展示覆盖时长、总时长占比、节点数量、可信度和重叠信息。

第一版分类如下：

| 分类 | 说明 |
| --- | --- |
| 工具执行 | 工具调用到匹配工具结果之间的时间区间 |
| 子代理执行 | 子代理委派到回执或可用结束时间之间的区间 |
| 委派与等待 | `spawn_agent`、`wait_agent`、handoff 等委派相关区间 |
| 上下文压缩 | compacted 和 context-compacted 相关处理区间 |
| 系统事件处理 | 其他具有完整时间区间的系统事件 |
| 未归因时间 | 会话墙钟区间中尚未映射到具体类别的时间 |
| 时间数据不足 | 存在事件但缺少可靠起点、终点或关联关系的项目 |

“助手生成与思考”保留为后续扩展分类。当前事件模型缺少稳定的模型生成开始和结束边界，页面将这部分时间纳入未归因时间或时间数据不足，并显示相应质量说明。

每个分类同时保留两种时长：

- `coverageMs`：该分类在会话时间轴上的覆盖时长。
- `nodeDurationMs`：相关节点耗时的累加值。

并行执行时，`nodeDurationMs` 可以大于 `coverageMs`。页面应显示重叠时长，例如：

```text
工具执行 · 8 分 12 秒 · 46.5% · 12 次
其中 1 分 40 秒与子代理执行重叠 · 混合
```

分类条使用实色表示已观测区间，使用斜纹表示估算区间。文本数值、状态文字和辅助标记共同表达含义，颜色只作为辅助编码。

## 6. 按轮次查看

按轮次的时间轴将统计结果放回会话过程。每个轮次展示：

- 轮次编号。
- 开始时间和结束时间。
- 轮次墙钟时长。
- 主要时间类别。
- 工具调用数和子代理数。
- 当前轮次的可信度。

每个轮次使用多轨道时间轴：

```text
第 3 轮 · 4 分 18 秒 · 混合

主轨道    助手上下文 ─ 工具执行 ─ 工具执行 ─ 最终回复
子轨道                     子代理执行 ─────────
辅助轨道                           上下文压缩
```

重叠的工具和子代理放在不同轨道上，以表达并行关系。区间宽度按所属轮次的时间范围归一化，轮次之间不共享比例尺。

时间区间可点击。点击后执行以下动作：

- 切换到“复盘”。
- 选中对应 Audit 节点。
- 打开右侧复核台。
- 保留当前轮次、节点和来源关系。

只有原始事件索引时，切换到“原始事件”并选中对应事件。来源可靠性不足的时间区间保留状态说明，并将跳转入口置为不可用。

## 7. 分类明细

点击分类后，在当前页面展开该分类的节点列表，按耗时降序排列：

```text
工具执行 · 8 分 12 秒 · 12 次

1. exec_command   3 分 26 秒   实测   第 2 轮
2. apply_patch    1 分 48 秒   实测   第 4 轮
3. exec_command   1 分 12 秒   估算   第 5 轮
4. spawn_agent    0 分 54 秒   估算   第 3 轮
```

明细项包含：

- 操作名称。
- 起止时间。
- 单项耗时。
- 所属轮次。
- 实测、估算或部分区间状态。
- 并行重叠提示。
- “查看复盘”入口。
- “查看原始事件”入口。

搜索或类型筛选后，明细标题显示当前范围：

```text
当前仅展示筛选命中的 5 项，顶部时间按完整会话计算
```

## 8. 时间数据质量

页面在时间分析末尾显示质量摘要：

```text
时间数据质量
整体口径：混合
已观测区间：18 项
估算区间：6 项
缺少结束时间：3 项
无法关联来源：2 项
存在并行重叠：4 分 12 秒
```

质量项可以点击并筛选对应问题。具体说明包括：

- 估算：结束时间来自最后一条事件或文件更新时间。
- 未完成：执行项只有开始事件。
- 缺少开始时间：只能确认结束事件。
- 来源不确定：工具结果无法匹配唯一调用。
- 并行重叠：该区间与其他执行区间同时存在。

会话文件变化、读取取消或读取结果不完整时，时间区域显示当前快照状态，并清理旧会话的时间数据和选择状态。

## 9. 服务端数据契约

会话详情接口新增统一的 `timing` 投影：

```js
timing: {
  version: 1,
  session: {
    startedAt: "2026-07-08T10:00:00.000Z",
    completedAt: "2026-07-08T10:18:42.000Z",
    durationMs: 1122000,
    durationKind: "estimated",
    coverageMs: 850000,
    coveragePercent: 75.9,
    parallelism: {
      peak: 3,
      overlapMs: 240000
    }
  },
  buckets: [
    {
      id: "tool_execution",
      label: "工具执行",
      coverageMs: 492000,
      nodeDurationMs: 560000,
      sharePercent: 44.0,
      count: 12,
      confidence: "mixed",
      overlapMs: 68000,
      nodeRefs: [
        {
          traceNodeId: "item:1:3:exec_command",
          turnIndex: 1,
          eventIndex: 18,
          durationMs: 42000,
          durationKind: "observed"
        }
      ]
    }
  ],
  turns: [],
  quality: {
    estimatedCount: 6,
    missingStartCount: 1,
    missingEndCount: 3,
    unlinkedCount: 2,
    notes: []
  }
}
```

字段约束：

- `durationMs` 使用非负整数毫秒，无法计算时为 `null`。
- `durationKind` 使用 `observed`、`estimated`、`partial`、`unavailable`。
- `confidence` 使用 `observed`、`mixed`、`estimated`、`unavailable`。
- `coverageMs` 表示时间轴覆盖，不等同于节点时长之和。
- `overlapMs` 表示分类内或分类间的并行重叠。
- `nodeRefs` 保存 `traceNodeId`、轮次索引和事件索引，用于回到复盘或原始事件。
- 搜索和类型筛选不改变 `timing` 的完整会话口径。

## 10. 模块职责

建议新增 `src/session-timing.mjs`，负责：

- 统一确定会话时间边界。
- 规范化时间区间并过滤负时长。
- 计算区间并集、重叠时长和并行峰值。
- 将 Trace 节点映射到时间分类。
- 标记实测、估算、部分和缺失区间。
- 生成轮次分布和质量摘要。

`server.mjs` 在构建详情时生成一次 `timing`。`public/app.js` 只消费该投影并负责渲染、筛选和跳转。复核台的会话时间范围也消费 `timing.session`，保持统计页、Trace 和复核台的口径一致。

## 11. 验收标准

### 数据与口径

- 完整会话显示总墙钟时长和可信度。
- 分类同时展示覆盖时长、节点时长累加值和并行重叠。
- 并行区间不会被重复计入总墙钟时长。
- 缺少起止时间的项目显示部分、估算或未记录状态。
- 无可用时间数据时显示原因，并保留事件统计和原始事件功能。

### 交互

- 分类明细可以回到对应 Audit 节点或原始事件。
- 轮次时间轴可以选中具体执行区间。
- 搜索和类型筛选不改变完整会话总时长。
- 切换会话、刷新和快照变化会清理旧 timing 及选中状态。

### 界面质量

- 时间条、分类和区间都有文本数值与可访问名称。
- 估算和并行状态不依赖颜色表达。
- 390px、1024px、1440px 视口下保持无横向溢出和文本遮挡。
- `prefers-reduced-motion` 下仍能完整理解时间关系。

### 测试

- `test/session-timing.test.mjs` 覆盖区间规范化、并集、重叠、分类、估算和缺失值。
- 服务端测试验证详情接口返回统一 `timing`，并覆盖文件变化、缓存和取消。
- E2E 测试覆盖普通会话、并行执行、缺少结束时间、筛选、跳转和移动端布局。
- 现有 Trace、Audit、统计和原始事件测试保持通过。
